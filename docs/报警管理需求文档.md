# 报警管理模块需求文档

## 1. 概述

报警管理模块用于配置订单异常状态的报警规则，支持根据不同店铺配置不同的报警人员，当订单触发指定异常状态时自动发送报警通知给相关人员。

## 3. 数据结构

### 3.1 报警规则数据模型

```typescript
interface AlertRule {
  id: string              // 规则ID，唯一标识
  name: string            // 规则名称
  shopIds: string[]       // 店铺ID列表（多选）
  triggerStatuses: string[] // 触发状态列表（多选）
  alertUserIds: string[]  // 报警人员ID列表（多选）
  alertMessage: string    // 报警提示语
  enabled: boolean        // 是否启用（开关状态）
  deprecated: boolean     // 是否已作废
  createdAt: string       // 创建时间
  createdBy: string       // 创建人
  updatedAt: string       // 更新时间
  updatedBy: string       // 更新人
}
```

## 4. 功能说明

### 4.1 搜索筛选功能

| 筛选项 | 类型 | 说明 |
|--------|------|------|
| 规则名称 | 输入框 | 模糊搜索 |
| 店铺ID | 输入框 | 精确匹配或模糊搜索 |
| 规则状态 | 下拉框 | 可选值：全部、使用中、已暂停、已作废 |

**操作按钮**：
- 「查询」：执行搜索
- 「新建规则」：打开新建弹窗

### 4.2 数据表格

#### 4.2.1 表格列定义

| 列名 | 字段 | 宽度 | 说明 |
|------|------|------|------|
| 规则ID | id | 80px | 唯一标识 |
| 规则名称 | name | 120px | 规则名称 |
| 开关 | enabled | 60px | Switch组件，控制规则启用/暂停 |
| 触发状态 | triggerStatuses | 150px | 多个状态用分号分隔显示 |
| 规则状态 | - | 80px | 根据enabled和deprecated计算显示 |
| 店铺ID | shopIds | 120px | 多个ID用分号分隔，超长截断 |
| 报警人员 | alertUserIds | 100px | 显示人员姓名，多个用分号分隔 |
| 提示语 | alertMessage | 150px | 超长截断，鼠标悬停显示完整内容 |
| 新建人 | createdBy | 100px | - |
| 新建时间 | createdAt | 150px | 格式：YYYY-MM-DD HH:mm:ss |
| 修改人 | updatedBy | 100px | - |
| 操作 | - | 120px | 操作按钮区 |

#### 4.2.2 规则状态显示逻辑

| 条件 | 显示状态 | 样式 |
|------|----------|------|
| deprecated = true | 已作废 | 灰色背景 + 灰色文字 |
| deprecated = false && enabled = true | 使用中 | 青色背景 + 青色文字 |
| deprecated = false && enabled = false | 已暂停 | 橙色背景 + 橙色文字 |

#### 4.2.3 开关列逻辑

- **功能**：控制规则的临时启用/暂停
- **启用状态**：开关打开，规则正常触发报警
- **暂停状态**：开关关闭，规则暂时不触发报警，可随时重新打开
- **禁用条件**：当规则已作废（deprecated = true）时，开关禁用不可操作

#### 4.2.4 操作列按钮

**未作废规则（deprecated = false）**：
| 按钮 | 功能 |
|------|------|
| 编辑 | 打开编辑弹窗，可修改规则配置 |
| 详情 | 打开详情弹窗（只读模式） |
| 作废 | 弹出确认框，确认后将规则标记为作废 |

**已作废规则（deprecated = true）**：
| 按钮 | 功能 |
|------|------|
| 详情 | 打开详情弹窗（只读模式） |

### 4.3 新建/编辑规则弹窗

#### 4.3.1 表单字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 规则名称 | 输入框 | 是 | 最大长度50字符 |
| 店铺ID | 输入框 + 标签 | 是 | 支持手动输入，按回车或点击添加按钮添加，支持多选 |
| 触发状态 | 下拉多选 | 是 | 带搜索功能，按分类分组显示，支持多选 |
| 报警人员 | 下拉多选 | 是 | 带搜索功能，直接显示人名列表（不分组），支持多选 |
| 报警提示语 | 文本域 | 否 | 可选，留空时自动生成默认提示语 |

#### 4.3.2 店铺ID输入交互

1. 用户在输入框输入店铺ID
2. 按回车键或点击「+」按钮添加
3. 已添加的店铺ID显示为标签
4. 点击标签上的「×」可删除
5. 同一店铺ID不可重复添加

#### 4.3.3 触发状态选择交互

1. 点击下拉框展开状态列表
2. 状态按分类分组显示（基础校验类、礼包状态异常、订单状态流转异常、接口异常）
3. 支持搜索过滤
4. 点击状态项切换选中状态
5. 已选状态显示为蓝色标签，可点击删除

#### 4.3.4 报警人员选择交互

1. 点击下拉框展开人员列表
2. 直接显示人员姓名列表（无分组）
3. 支持搜索过滤
4. 点击人员项切换选中状态
5. 已选人员显示为灰色标签，可点击删除

#### 4.3.5 表单验证规则

- 规则名称：必填，非空
- 店铺ID：必填，至少选择1个
- 触发状态：必填，至少选择1个
- 报警人员：必填，至少选择1人
- 报警提示语：可选

### 4.4 作废功能

#### 4.4.1 作废确认流程

1. 点击「作废」按钮
2. 弹出确认对话框：「确定要作废此报警规则吗？作废后该规则将不再触发报警。」
3. 点击「确认作废」执行作废操作
4. 点击「取消」关闭对话框

#### 4.4.2 作废后的规则状态

- `deprecated` 字段设为 `true`
- `enabled` 字段设为 `false`
- 开关禁用不可操作
- 操作列只显示「详情」按钮
- 规则状态显示为「已作废」

**注意**：作废操作不可逆，作废后的规则无法恢复或编辑。

### 4.5 分页功能

| 配置项 | 可选值 |
|--------|--------|
| 每页条数 | 20条/页、50条/页、100条/页 |
| 分页导航 | 上一页、页码、下一页 |

## 5. 接口需求

### 5.1 获取规则列表

```
GET /api/alert-rules

请求参数：
- name?: string        // 规则名称（模糊搜索）
- shopId?: string      // 店铺ID
- status?: string      // 规则状态：all | active | paused | deprecated
- page: number         // 页码
- pageSize: number     // 每页条数

响应：
{
  code: number,
  data: {
    list: AlertRule[],
    total: number,
    page: number,
    pageSize: number
  }
}
```

### 5.2 创建规则

```
POST /api/alert-rules

请求体：
{
  name: string,
  shopIds: string[],
  triggerStatuses: string[],
  alertUserIds: string[],
  alertMessage?: string
}

响应：
{
  code: number,
  data: AlertRule
}
```

### 5.3 更新规则

```
PUT /api/alert-rules/:id

请求体：
{
  name?: string,
  shopIds?: string[],
  triggerStatuses?: string[],
  alertUserIds?: string[],
  alertMessage?: string,
  enabled?: boolean
}

响应：
{
  code: number,
  data: AlertRule
}
```

### 5.4 切换规则启用状态

```
PATCH /api/alert-rules/:id/toggle

响应：
{
  code: number,
  data: {
    enabled: boolean
  }
}
```

### 5.5 作废规则

```
PATCH /api/alert-rules/:id/deprecate

响应：
{
  code: number,
  data: {
    deprecated: boolean
  }
}
```

### 5.6 获取系统人员列表

```
GET /api/system-users

响应：
{
  code: number,
  data: Array<{
    id: string,
    name: string
  }>
}
```

## 6. 业务规则

### 6.1 报警触发逻辑

当订单状态发生变化时：
1. 查询所有 `enabled = true` 且 `deprecated = false` 的规则
2. 匹配规则的 `shopIds` 是否包含当前订单的店铺ID
3. 匹配规则的 `triggerStatuses` 是否包含当前订单的异常状态
4. 如果匹配成功，向规则配置的 `alertUserIds` 对应的人员发送报警通知
5. 报警内容使用规则配置的 `alertMessage`

### 6.2 权限控制（建议）

| 操作 | 权限要求 |
|------|----------|
| 查看列表 | 登录用户 |
| 新建规则 | 管理员/运营 |
| 编辑规则 | 管理员/运营 |
| 切换开关 | 管理员/运营 |
| 作废规则 | 管理员 |

## 8. 注意事项

1. 店铺ID由用户手动输入，系统不做格式校验，由业务方自行保证正确性
2. 作废操作不可逆，需在确认弹窗中明确提示用户
3. 开关状态变更应立即生效，无需页面刷新
4. 表格中超长文本需做截断处理，鼠标悬停显示完整内容
5. 所有时间显示格式统一为：YYYY-MM-DD HH:mm:ss
